# [M] P-256 runs pyca/verified-garbage's code where it is faster

## Goal

On each tier below where pyca/verified-garbage (VG) measured at least as fast as rind at every size, P-256 key agreement and ECDSA runs VG's routine under rind's glue and behavior.

## Plan

- Measured in [run 43531095881](https://github.com/kixel-ai/rind/actions/runs/43531095881) (the nightly `bench` workflow dispatched on [kixel-ai/rind#741](https://github.com/kixel-ai/rind/pull/741) at VG `d004ffae`) and on the report's hosts, as [the epic](/quest/m2/verified-garbage/README.md) records. Ratios are VG's time over rind's.
- Take VG's lowest routine that leaves rind's API and behavior intact and keep rind's glue, as the epic's Plan settles. Vendor it with `admin/import-vg`, which the first switch to land adds.
- Re-measure each cell below before and after on the nightly's tiers and an idle host, and switch only the cells that still hold at every size; every other tier keeps rind's code.
- Wycheproof and the aws-lc-rs differential tests already cover the operation; extend the ctgrind tests to the new code path.

Cells VG won:

- x86_64 with AVX-512 (the native row drew a Zen 4 EPYC 9V74): every operation, 0.50 (verify) to 1.00 (ECDSA key generation); ECDH 0.68, signing 0.90.
- aarch64 (Neoverse N2), with and without the crypto extension: every operation, 0.85 to 0.97.
- x86_64 without AVX2: signing 0.98 and verification 0.91; ECDH loses (1.10).
- x86_64 without ADX: verification 0.91; ECDH (1.13) and signing (1.16) lose.
- `desktop` (Arrow Lake, AVX2 and VAES, under load): every operation, 0.77 to 0.97. Recheck on an idle host; the no AVX-512 tier did not time P-256.
- Lost: the Haswell VPSes (ECDH 1.21, signing 1.15 to 1.17, verification 1.01).
