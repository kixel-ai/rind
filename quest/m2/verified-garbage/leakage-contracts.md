# [M] rind imports pyca/verified-garbage's leakage contracts, and retires the harnesses they cover

## Goal

For each VG routine rind runs, its leakage theorem is imported as an axiom about the routine's artifact on VG's model, stated with the vendored `VerifiedGarbage/TCB/Artifact.lean`'s own trace definitions and citing VG's theorem at the pinned revision, with `admin/vg-bytes` checking that rind's build emits that artifact's bytes. Today it compares instruction bytes and relocations by the symbol's last path component only; extend it to bind each relocation's full target and the contents of the statics it reaches before any harness retires: the routine's address and branch trace depends only on what its contract declares public. It says nothing about rind's Rust wrapper, so [the composition rule](/quest/m4/verified/README.md#composition-rule)'s one functional axiom per wrapper is unchanged; `Axioms.lean` pins the new axioms too. The dedicated constant-time harness of each such routine is removed: `ct_sde_…` for VG's ML-KEM-768 and P-256 on x86_64, `ct_qemu_…` for its aarch64 SVE2 ChaCha20-Poly1305, and any `ct_binsec_…` region over only VG code. TESTING.md's constant-time column cites the theorem instead.

## Plan

Follow-up from the 2026-11-18 /quest-plan on independence and Lean, which settled with the maintainer: ✅ once a routine's leakage contract is proven in Lean, its dedicated trace harness is retired, and ctgrind keeps running every test (rejected: keep every harness). VG already proves these contracts (`VerifiedGarbage/TCB/Artifact.lean`). Today rind restates only what each wrapper returns (`Rind/VgOutcome.lean`, `Rind/<Arch>/VgMlKem.lean`), so the harnesses still carry the claim. Kept as a follow-up by the maintainer on 2026-11-18, on [kixel-ai/rind#893](https://github.com/kixel-ai/rind/pull/893): ✅ keep (rejected: drop).

- A contract's declared leakage, such as a rejection-sampling count, must be public in rind's call too. Check each against the Rust that calls the routine, and keep the harness for any routine whose declared leakage rind's caller treats as secret.
- The theorems need the cosimulation that the ✓ needs, which `admin/prove vg` already runs for these instructions. The stack-slot model gap recorded in [the epic](/quest/m2/verified-garbage/README.md) holds back only the routines it holds back there.
- Where rind's Rust feeds a VG routine, ctgrind and BINSEC still check that Rust. An SDE or QEMU harness also traces the wrapper on a path valgrind cannot run and BINSEC does not decode (AVX-512, SVE2), so before retiring one, give that wrapper a retained trace check, such as a BINSEC region over it with the VG routine stubbed by its contract, and say which in the PR. Retire a BINSEC region only when it covers VG code alone.

## Waiting

- Maintainer: how each leakage axiom names the routine's code. VG's `Verified T c k` is about `c`, the routine's `Prog`, which VG builds from its `Impl/` modules. Options: (a) vendor each routine's `Impl/` closure byte for byte, which `admin/import-vg-models` bounds and checks against the pin, and state `Verified`'s constant-time conjunct (`ConstantTime`) of VG's own `Prog` (`Cosim/Progs.lean`, `Cosim/ProgsX86_64.lean`), with `admin/vg-bytes --progs` checking that VG's printer's text of each `Prog`, and of every function it calls, is VG's assembly line for line, and rind's machine code against that text; (b) generate each `Prog` from VG's printed text with `Cosim/`'s parser and bind that text to rind's bytes, vendoring no `Impl/`; (c) an opaque `Prog` constant per routine, which vendors nothing but says nothing about rind's bytes. This PR implements (a), not yet decided: aarch64 SVE2 ChaCha20-Poly1305 (`Rind.Aarch64.VgChaCha20Poly1305Ct`, about 2,900 added Lean lines) and x86_64 ML-KEM-768 (`Rind.X86_64.VgMlKem768Ct`, about 7,400: ten axioms, key generation and decapsulation with AVX-512 and encapsulation, with `H(ek)` given or not, at each of its four widths, each `Prog` the routine with the scrub VG appends); P-256 IFMA ECDH on x86_64 would add about 19,000 by the same steps. Under (a) the link from `Prog` to bytes rests on VG's vendored printer, which is in the trusted base and not injective in general (it prints `frame` and `block` alike). Recommendation: (a), as implemented. Only (a) states the axiom of the very term VG's theorem is about; (b) needs its parsed `Prog` to equal VG's, which rests on the same printer being injective plus the parser covering whole routines, so it trusts more, not less; (c) proves nothing about rind's code. The vendored lines are mechanical and checked byte-identical to VG at the pin. Clear it by choosing one; (b) or (c) replaces this PR's vendored `Impl/` closures and `Cosim/Progs*.lean`.
- Maintainer: the retained trace check for each wrapper whose SDE or QEMU harness retires. No `ct_binsec_...` region decodes AVX-512 or SVE2, so `ct_sde_mlkem768` (rind's `keygen_internal`, `encaps_internal`, `decaps`, which are rind's Rust around VG's routines), `ct_sde_p256_ifma_ecdh`, and `ct_qemu_chacha20poly1305` would leave their wrappers without a trace check. Either BINSEC gains those decoders, or a region stubs the VG routine by its contract on the portable parts, or the maintainer accepts ctgrind alone for the part of each wrapper valgrind runs. Until then `ct_qemu_chacha20poly1305` and `ct_sde_mlkem768` stay, though their routines' leakage is now an axiom. For `ct_sde_mlkem768` the retained check would be a BINSEC region over `DecapKey::decaps`, `EncapKey::encaps_internal`, and `DecapKey::keygen_internal` as the x86_64 build compiles them, with each `vg_mlkem768_*` routine stubbed by its contract (its secret outputs fresh secret bytes, its leak `ρ` public), so that BINSEC covers rind's Rust around the routine, which it decodes, and not VG's AVX-512 code, which it does not and the axiom covers; the SDE harness is the only trace of that Rust on the AVX-512 path, so it goes only with that region. Recommendation: the stubbed BINSEC region, for each of the three wrappers: BINSEC already decodes the wrappers' Rust, stubbing each routine by its contract is the composition the leakage axioms license, and it keeps a trace check on every path while the SDE and QEMU harnesses retire; new BINSEC decoders are open-ended upstream work, and ctgrind alone leaves the AVX-512 and SVE2 paths' Rust untraced. Clear it by choosing one.

Checked for the Plan's first bullet, at VG `0aa40d6c`: each declared leak is public in rind's caller. ML-KEM-768's `leakRho` is `ρ`, which is in the encapsulation key; P-256 ECDH's `leak` is the peer's public key bytes; ChaCha20-Poly1305 open's `openLeak` is whether it returns 1, which rind returns. So no harness stays for that reason.
