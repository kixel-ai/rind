# [XS] rind on 32-bit x86 at the MSRV

## Goal

rind and rind-rustls build for 32-bit x86 (`i686`) on the workspace's 1.90 MSRV, as they do on every other target, so [PLATFORMS.md](/PLATFORMS.md) and the README drop their 1.94 exception.

## Plan

CI already tests i686 Linux, Windows, and Android on stable. Only libcrux-platform 0.0.4, which libcrux-aes pulls in, needs Rust 1.94 there: it calls `__cpuid` outside `unsafe`, which compiles only since `__cpuid` became safe in 1.94. Raising rind's MSRV to 1.94 for one target would raise every consumer's, moq's 1.91 library floor among them, so this waits for libcrux instead. Once a fixed libcrux-platform is released, bump to it, check i686 in `sh/dispatch.sh`'s `msrv` module (adding the target to the flake's `msrv` shell), and drop the exception.

## Waiting

- celabshq/libcrux: release a libcrux-platform that calls `__cpuid` inside `unsafe`, tracked in [celabshq/libcrux#1646](https://github.com/celabshq/libcrux/issues/1646); check with `cargo update -p libcrux-platform` and a 1.90 `cargo check -p rind --target i686-unknown-linux-gnu`
